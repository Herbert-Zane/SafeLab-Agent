# SafeLab 控制台（基础版）

只读地查看 `runs/` 下的运行目录：智能体想做什么、审查器怎么判、依据是什么、实际执行了什么、状态怎么变。
纯 Python 标准库后端加原生 HTML、CSS、JS，不依赖任何 CDN 或联网安装，断网可用。

## 启动

```powershell
.venv\Scripts\python.exe console\server.py --runs runs
```

浏览器打开 <http://127.0.0.1:8765/>。选项：`--port`、`--host`（默认只监听本机）。
直接打开某个运行：`http://127.0.0.1:8765/?run=dry/C_flash_wsopen_1`。
Ctrl+C 退出；由页面启动的子进程会一并结束。

## 文件

| 文件 | 作用 |
|---|---|
| `server.py` | HTTP 服务、JSON 接口、离线运行的启动 |
| `runstore.py` | 数据层：读运行目录，把 trace 事件归到每一步，重建账本，判定来源 |
| `web/index.html`、`web/app.js`、`web/style.css` | 单页界面 |
| `tests/test_console_runstore.py`、`tests/test_console_server.py` | 测试 |

## 数据来源与读取的文件

运行目录里只读这些：`agent_run.json`、`agent_steps.jsonl`、`agent_plan.json`、`agent_conversation.json`、
`agent_system_prompt.txt`、`trajectory_evaluation.json`、`safelab_trace.jsonl`、`actions.jsonl`（仿真的动作日志，有才读）、
`run_meta.json`（运行元数据，有才读）。
批次目录（运行目录的上两级）里另外只读两个标记文件 `MOVED.txt`、`SUPERSEDED.txt` 的第一行，见“结果表”一节。
不读平台的 `configs/knowledge/`，也不读任务的 criteria；评测器内容只来自运行目录里已有的 `trajectory_evaluation.json`。

页面顶部固定显示数据来源：

- **仿真**：`agent_run.json` 的 `environment.environment` 是 `simulation`。
- **干跑（离线推演）**：`environment` 是 `dry_run`，或观测的 `source` 是 `dry_run`。干跑不给任何安全、完整性、目标结论。
- **录像回放**：回放模式下显示，旁边保留“原始运行”的来源。
- **来源未知**：目录里没有说明来源，按未评估处理。仅有评测文件不足以判定为仿真。

评测器面板的措辞规则：评测器的 `no_detected_consequence` 显示为“未检出后果（仅限已声明覆盖范围，不等于安全）”；
`not_assessed`、`unknown` 和任何没见过的状态都显示为“未评估”。干跑旁边若有评测文件（计划级推演），会加黄色横幅说明它不是仿真结果。

后果对应到哪一步：评测文件里每条后果带 `occurred_time_s` 时，面板写明它落在哪一步执行期间、哪两步之间，或不在记录范围内；
能对应到步骤的是链接，点击跳到那一步。步骤的起止时间优先取 `actions.jsonl`（`start_time_s`、`end_time_s`），没有这个文件时
按 `agent_steps.jsonl` 里每步结束时的累计仿真时间推算，并在面板上注明是推算。两者都没有，或后果没有时间，显示“未评估”。
这与平台 `scripts/consequence_trace.py` 的归属方法相同，但控制台不调用平台脚本，只读运行目录里的文件。

## 面板

1. **运行列表**：按条件、任务、模型、来源筛选。“启动离线运行”只开放 `configs/agents/safelab_B.json`、`safelab_C.json`
   （均为 `plan_replay`，规则通道，不调用模型），调用 `scripts/run_dry.py`，产物写到 `runs/dry/<条件>_<任务>_console_<时间>`。
   启动前服务端会再检查配置：任一角色不是 `plan_replay`、审查器不是纯规则、或文件里出现 `api_key`/`base_url` 就拒绝。
   条件 A′ 单独筛选：优先识别 `run_meta.json` 的 `condition: "Ap"`，否则识别 brief 文件名中的 `.primed.`。
   列表搜索最深五层，包含只有 `run_meta.json` 的目录；标注“正式运行 / 探索性（非正式）/ 已搁置（不是结果）”和“排除”，可按性质和批次筛选。运行头部显示是否正式、处置及排除原因、
   外层上限终止、区组与位次、补跑次数、两个提交号的前七位。上限终止且没有评测时写明“被外层时间上限终止，没有评测输出”。
   所有日志时刻按浏览器本地时区显示，头部标明 UTC 偏移和时区名称；回放仍使用原始时间戳。
2. **阶段计划**：当前计划版本及每个阶段的状态，随回放或日志推进；重规划后显示新版本和原因。
3. **每步时间线**：候选动作 → 审查结论 → 实际执行 → 回读变化。审查结论分规则通道（规则 id、知识卡片 id、证据路径及取值、
   改写建议）和 LLM 通道（是否触发、结论、卡片、证据、置信度）。驳回的步骤红色左边框，改写的橙色；同一步内多次提议、
   驳回后重提议都按顺序列出，并标注是按驳回理由重提议还是重规划后提议。反思、重规划、阶段切换列在同一步下面。
   无效回复显示“无效回复（平台未执行）”及平台报错，与同一 `step_index` 的重试分开；失败动作显示“执行失败”及原始原因。
4. **账本**：容器、枪头（状态与接触史）、设备、未确认项，以及本步 diff；本步变化的条目高亮。点击任一步切换。
   机器人栏合并账本 `held_object` 与观测 `held_object_id` 的重复显示；手持工具单列。两个物体字段若有不同的非空值，分别标明账本与观测。
5. **Token、费用、时延**：合计、按角色、每步“可见时延”条形图（超过 15 秒标红，对应执行规划 S3.4 的目标）。
   缺失的每步/角色费用与时延显示“—”；无角色费用时合计取 `agent_run.json` 的平台汇总，并注明整次运行的来源。
   无 trace 时只使用平台明确记录的 `reply.latency_s`，不从同一条记录的时间戳推算决策耗时；每步 token 可取累计量之差。
6. **评测器**：`task_completion` 标为“终态液体目标（task_completion）”，说明“只核对终态液体量与成分、枪头状态和体积守恒，
   不核对流程是否做完。”目标检查按目标、状态、实际值、期望值制表，未达成行高亮，`evidence` 默认折叠。
   仿真秒数显示两位小数；没有评测输出时为“未评估”。安全措辞规则见上。

## 三种查看方式

- **静态查看**：显示整个运行。
- **实时跟踪**：每 1.5 秒按文件签名轮询，日志文件增长时自动追加新步骤并跟随最新一步；运行结束后自动转为静态。
  最近 120 秒内有写入且没有 `run_end` 的运行被视为“进行中”，选择它时默认进入实时跟踪。
- **录像回放**：按日志里每个事件的原始时间戳回放，可播放、暂停、单步、退一步、拖动进度，倍速 1/2/5/10/30/100，
  可勾选“空档最多等 2 秒”压缩模型思考的长空档。

## 没有 safelab_trace 的运行（条件 A、A′、脚本回放）

用 `agent_steps.jsonl` 退化显示：每个平台调用一步，标“无审查器”，没有阶段计划；回读变化来自相邻两次观测的差，
账本面板是由观测还原的状态（没有枪头接触史），并明确标注。

## 结果表

顶栏点击“结果表”，或直接打开 `/?view=tables`。每个“批次 × 性质”单独一张表；批次是运行目录的上两级目录相对
`--runs` 的路径，根目录记为 `.`。性质有四种，表按这个顺序排（正式运行在最前）：

- **正式运行**：`run_meta.formal` 为 `true`。
- **探索性（非正式）**：`run_meta.formal` 为 `false`。表头写明“未预注册，不与正式运行合并报告”。
- **已搁置（不是结果）**：批次目录里有标记文件 `MOVED.txt` 或 `SUPERSEDED.txt`（内容的第一行作为原因显示）。
  这类批次的元数据可能仍写着 `formal: true`、`counted`，目录里也可能有评测文件（例如 402 余额不足时空轨迹的评测），
  所以不按元数据归入正式运行：表里只列运行，不给任何计数，下钻、单运行头部、评测器面板和并排回放一律显示“未评估”。
  正式运行里按预注册修订 5 搁置的 90 次（`formal_402_aside/MOVED.txt`，服务器上移走时写的）和本机重跑前的中途备份
  （`runs/formal_s52d09cf/formal/SUPERSEDED.txt`，11-14 手工加的，没有改动运行文件）都靠这个标记区分。
- **干跑**：`run_meta.mode` 为 `dry`，优先于其余三种。不给评测结论。

不跨批次或性质合并。元数据缺失、不合法的运行只计入 `skipped`，仍可从运行列表查看。
没有标记的批次里若有结局为 `backend_error` 的运行，表上方给出黄色提示和次数；这些运行仍按元数据计数，控制台不替你排除。

计数口径同 `experiments/analyze.py` 的主分析，控制台不导入分析模块。排除项不进分母；分母 `n` 是 counted 且有可读评测文件的
仿真运行。三个指标只使用评测文件的 status，以及安全和完整性的 unassessed / coverage，不读取 checks 或后果详情。
事件分别为 `unsafe`、`failed`、`achieved`；未知状态、非空 unassessed 或空 coverage 按对应规则计入“未评估”。
缺评测单列；干跑不给评测结论。未检出后果不等于安全。裂解安全格按常规显示原始检出计数，下钻与单运行按评测器原始 status 显示。
裂解任务附完整性覆盖说明：“用过的枪头回到试剂瓶”这类污染记在完整性维度（cross_contamination），已用固定动作序列确认可检出
（探索性核实，见 `experiments/results/evaluator_coverage_lysis/report.md`）；安全维度只覆盖评测器声明的其他后果类型。
覆盖说明以普通说明文字显示，不作为结论，也不改变计数。“评测器自报未评估”一列仍只数评测文件自己报告的未评估
（非空 unassessed、空 coverage、未知状态）。
区间、检验及结论措辞以 `experiments/results/` 的 `results.md` 为准，控制台不计算区间或 p 值，不生成结论。

点击数字（包括 0）在表下列出对应运行；指标格列出分母全部运行，将事件运行放在前面并高亮。点击条件可查看该行所有运行。
可“打开”或与同批次、同性质、同组、同任务、同序号的其他条件“并排”查看；并排时条件靠前的一侧（A、A′、B、C 的顺序）固定在左边，
与从哪一行点进去无关。下钻表下方有一行说明“未检出”和“未评估”各指什么。
`/?view=tables&batch=<编码后的批次>&sel=<编码后的选择JSON>` 保存下钻；点击生成的链接即可，刷新、前进后退均可恢复。
从表打开运行后，头部的“← 返回结果表”恢复原选择。

## 并排回放

入口是下钻中的“并排”链接、单运行头部的“并排对照”下拉，或
`/?left=<encodeURIComponent编码的运行id>&right=<encodeURIComponent编码的运行id>`。
例如 `/?left=formal%2Fopen%2FA_ws_03&right=formal%2Fopen%2FC_ws_03`（以 `--runs` 的相对路径为准）。
父页面用一个控制条驱动两个同源 iframe（子页 `/?run=<编码后的id>&embed=1`）。嵌入页隐藏侧栏和自己的播放条，
固定为回放，依次显示紧凑头部、评测器、阶段计划、每步时间线，以及折叠的账本和费用。

- **按步号**（默认）：共享平台调用步序（时间线上每一行算一步，含该步全部事件），步数较少的一侧到结尾后停留；
  播放按 `max(150, 3000/倍速)` 毫秒推进一步，单步为 ±1。两侧的第 k 步并排，适合看同一步上基线照做、审查器驳回。
- **按经过时间**：以各自第一个事件为零点，共享经过时间，持续到较长的一侧结束；可将每侧超过 2 秒的相邻空档压成 2 秒。
  单步和退一步跳到两侧合并后的下一或上一事件时刻。压缩空档后两侧的快慢取决于各自日志里的事件个数
  （没有 `safelab_trace` 的一侧每步只有一个时间戳），不代表真实耗时，所以不作默认。

支持播放/暂停、1/2/5/10/30/100 倍速、回到开头、跳到结尾和拖动进度。每侧标题下有一行状态：已完成几步；
该侧到自己的结尾后才显示三个维度的评测结论（终态液体目标、科学完整性、安全），提前只提示评测在回合结束后产出。
这一行的措辞：`no_detected_consequence` 写“未检出后果”（悬停显示完整说明，控制条下方固定有一行“不等于安全”的说明）；
裂解安全维度按评测器原始 status 常规显示，完整性维度附近附覆盖说明；没有评测输出、非仿真来源、已搁置的运行都写“未评估”。
父页面保留两侧各自的原始来源；干跑仍明确标为离线推演，不作为仿真结果。
任务、brief 组、批次、性质不同或缺少可核对的元数据时显示黄色提示“只供查看，不能当作同批对照”。
一侧 id 无效或读取失败，另一侧仍可回放或单独打开。

## JSON 接口

`GET /api/runs`、`/api/run?id=<id>[&sig=<sig>]`（签名未变时返回 `{"unchanged": true}`）、`/api/ledger?id=&call=`、
`/api/step?id=&step=`（完整的平台记录，含完整回复和推理）、`/api/tables`（批次表、下钻简表和 skipped）、
`/api/options`、`/api/jobs`；`POST /api/start`。
`id` 是相对 `--runs` 的路径，例如 `dry/C_flash_wsopen_1`；含 `..` 或指向目录外的 id 一律拒绝。
`POST` 带有 `Origin` 且与 `Host` 不同时返回 403。

## 测试

```powershell
.venv\Scripts\python.exe -m pytest -q tests/test_console_*.py
```

用合成运行目录测数据层和接口；用到真实录像（`runs/dry/C_flash_wsopen_1`）的用例在文件缺失时跳过；
另有真实 `integ2` 仿真和 `cap_sim` 上限终止产物的回归用例，样例缺失时跳过。
真正启动离线运行的用例用 `bench` 夹具，平台不可用时跳过。
原生 JS 的轻量 DOM 检查覆盖主要展示、目标表与证据折叠、条件筛选，以及三个时区的显示和原始回放时间；没有 Node 时跳过这些检查。
新增批次边界、三种性质、逐格对照主分析、缓存失效与路径检查，以及结果表下钻和并排定位的原生 JS 检查。
真实目录回归核对正式 110 次的 14 格计数。`formal_402_aside` 的 90 次元数据是 `sim / formal / counted` 且都有可读评测文件，
回归用例核对它们因 `MOVED.txt` 归入“已搁置”、不出现在正式运行的表里、不给计数；合成用例核对加上标记文件后缓存立即失效。
`/api/runs` 和 `/api/tables` 按运行 id 与允许文件的大小、mtime 签名以及批次标记缓存；进行中的运行每次重读，其余只在文件变化时重读。
缓存容量要大于运行个数（现为 8192 项）：11-14 发现原先 512 项小于本机的 577 个运行，列表行互相挤出缓存，每次请求都重算（约 3 秒）。
